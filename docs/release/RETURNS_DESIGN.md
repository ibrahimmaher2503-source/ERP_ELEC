# تصميم مرتجعات البيع والمشتريات — 2026-11-04

قرار المالك: تنفيذ المرتجعات الفعلية ضمن هذا التسليم. المرجع: WF-03 في `docs/CROSS_MODULE_WORKFLOWS.md` وعقد القيود في `docs/05-MODULE-CONTRACTS-EVENTS.md`.

## الملكية

- `Sales` يملك مستند مرتجع العميل، و`Purchasing` يملك مستند مرتجع المورد، بنفس نمط `SalesDeliveries`. لا توجد وحدة `DeliveryReturns` في الكود، ولا تُنشأ لهذا الغرض.
- `Inventory` يملك الحركة والتكلفة. `ReceivablesPayables` يملك إشعار التصحيح. `Accounting` يملك القيد. لا كتابة عبر الوحدات إلا من خلال الـ API.

## دورة الحياة

`draft` ← (`posted` أو `rejected`).

1. مُعد المرتجع ينشئ مسودة، بدون أي أثر مخزني أو مالي.
2. مستخدم مختلف يعتمد. الاعتماد يرحّل الحركة المخزنية وإشعار التصحيح والمستند الرسمي في معاملة واحدة. أي فشل يلغي الكل.
3. الرفض يحرر الكمية المحجوزة بالمسودة، بدون أي أثر.

## قواعد الأهلية

- كمية المرتجع لا تتجاوز: الكمية المفوترة المرحّلة ناقص المرتجعات السابقة والمسودات المفتوحة.
- المسلّم أو المستلم غير المفوتر لا يُرتجع في هذا الإصدار، ويلزم إصدار الفاتورة أولًا. هذا يبقي مساري `GRNI` والتسليم غير المفوتر بدون تغيير.
- الأصناف المسلسلة: السيريال لازم يكون نفس السيريال الأصلي للتسليم أو الاستلام.
- فواتير عقود الخدمة والورش والصيانة ليست مصدرًا لهذه الشاشات.

## مرتجع العميل

- عملية مخزنية جديدة `sales_return`، و`reversal_id` يشير إلى حركة `reservation_issue` الأصلية.
- ترجع بتكلفة FIFO الأصلية وتاريخ طبقتها عبر `ValuedCorrections`. لو الحركة الأصلية موزعة على أكثر من طبقة، تُقسم الكمية حسب الطبقات.
- القيد: مدين `inventory` / دائن `cogs`.
- الحالة `damaged`: تدخل المخزون ثم تُعزل عبر `InventoryConditions`، فلا تكون متاحة للبيع.
- الإشعار: مدين `sales` و`tax_output` / دائن `receivable`، بقيم بند الفاتورة نفسه لا بنسبة إجمالي الفاتورة.
- لو الفاتورة مسددة، الزيادة تتحول إلى رصيد دائن قابل للرد في `rp_party_credits` عبر المسار الحالي.

## مرتجع المورد

- عملية مخزنية جديدة `supplier_return`، تستهلك من طبقة FIFO الأصلية للاستلام. لو الطبقة نفدت، تظهر رسالة واضحة ولا يتم الترحيل.
- العقد القديم يذكر المتوسط المتحرك، لكن النظام كله FIFO، فالمعتمد هو تكلفة الطبقة الأصلية.
- قيد الحركة: مدين `ppv` / دائن `inventory` بالتكلفة C.
- قيد الإشعار الحالي: مدين `ap` / دائن `ppv` / دائن `tax_input`. صافي `ppv` = C ناقص N، وهو نفس أثر عقد الحسابات، بدون ربط حساب جديد قد يكسر الإعدادات المفعلة.

## إشعار التصحيح

- مسار مخصص `createReturnCreditNote` بعمود مصدر فريد، بدل المبلغ الحر.
- الصافي والضريبة يُحسبان تراكميًا من بند الفاتورة، بحيث آخر كمية تستنفد القيمة بالضبط.
- `created_by` هو مُعد المرتجع و`approved_by` هو المعتمد، وقيد قاعدة البيانات يمنع تطابقهما.

## الحماية

- Trigger مؤجل يرفض أي حركة `sales_return` أو `supplier_return` بدون مستند مرتجع مرحّل ورابط إشعار وتكلفة مطابقة.
- مفتاح idempotency لكل بند، وقفل على مصدر البند لمنع الإرجاع المتزامن لنفس الكمية أو السيريال.

## الصلاحيات والمسارات

## خارج هذا الإصدار

- مرتجع غير مفوتر.
- إعادة فتح أمر البيع أو الشراء تلقائيًا بعد المرتجع. الاستبدال يتم بأمر جديد.
- إلغاء مرتجع مرحّل. التصحيح يتم بمستند جديد مرتبط.
