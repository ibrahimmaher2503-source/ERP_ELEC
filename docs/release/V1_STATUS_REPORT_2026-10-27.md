## ما أُنجز في دورة الشحن الحالية

- إنشاء مصفوفة V1 بمسارات `SHIP` و`BLOCKED` و`DEFER`، وحجب واجهات V2 بدل عرض صفحات متاحة ظاهريًا.
- إصلاح هجرات دوال PostgreSQL للمشروعات حتى تقبل إعادة بناء قاعدة الاختبار دون تعارض أسماء الدوال.
- إصلاح قراءة تحويلات المخزون بحيث تتطلب صلاحية تغطي المصدر والوجهة؛ نجح فحص العودة بعدها.
- نجاح `npm run build` و`php artisan view:cache` وفحص تنسيق PHP للملفات التي عُدلت آنذاك. فحص Pint الشامل أظهر مخالفات أقدم في ملفات أخرى.
- نجاح `php artisan test`: **37 اختبارًا، 94 تحققًا**. يشمل هذا حزمة Laravel الأساسية؛ فحوص أصحاب الأعمال المستقلة موضحة أدناه. شُغّل هذا قبل ظهور ملفات التنفيذ المالي الجديدة في مساحة العمل.
- نجاح جولة المتصفح لأمر الشراء والجرد عبر سطح المكتب والهاتف، RTL وLTR اصطناعي فقط، مع ملفات CSS/JS والخطوط المستضافة بنجاح. LTR هنا فحص اتجاه، لا تعريب/ترجمة إنجليزية.

## P0 / P1 المتبقية

1. **P0 — السياسة التجارية/الضريبية والافتتاح المالي:** يلزم تحديد قاعدة الضريبة والتقريب ومصدر أرصدة الافتتاح وحدّ القطع قبل تفعيل مستندات أو ترحيل رسمي. لا يجوز ملء الفجوة بأرقام أو موافقات اصطناعية.
2. **P0 — رحلة البيع:** الإصدار الرسمي للعروض واعتماد البيع والحجز/التسليم الحقيقي غير مثبتة، ولا يوجد قبول متصل حتى خصم المخزون.
3. **P0 — رحلة الشراء:** إصدار PO حقيقي ثم استلام ذري إلى المخزون وFIFO وGRNI مع الجزئي/النهائي، التكرار والتنافس؛ ملفات التنفيذ الجديدة لم تجتز قبولًا بعد.
4. **P0 — ترحيل ومصالحة المخزون المالي:** المصدر والتكلفة والقيد المتوازن والافتتاح المعتمد لم تثبت كرحلة تشغيل كاملة.
5. **P1 — قبول العمل الجديد:** مساحة العمل تضم تغييرات غير ملتزمة للترقيم/PDF/التهيئة المالية والترحيل، إضافة إلى تغييرات في العقود والواجهات والهجرات. تحتاج مراجعة تكامل واختبارات PostgreSQL والمتصفح بعد استقرارها؛ نتائج اليوم السابقة لا تصادق على هذه النسخة المتحركة.
6. **P1 — التشغيل والتعافي:** إكمال نسخة الملفات الخاصة، استعادة كاملة، ودليل تثبيت نظيف؛ ثم إعادة فحص البيانات الرئيسية والمتصفح وأزرار V1 المرئية.
