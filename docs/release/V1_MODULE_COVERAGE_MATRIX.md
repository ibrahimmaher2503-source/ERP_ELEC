## Measurement method

Inventory is derived from the actual `app/Modules` directories, route/component bindings, migrations and public contracts. Eleven physical owners exist. A screen, model, permission key or test that asserts a deliberate refusal is not a completed business requirement.

For a percentage to be valid, its denominator must be a current, frozen set of uniquely identified requirements mapped to present source and current acceptance evidence. No such verified whole-module baseline exists here. The older Purchasing 32-row and Inventory 34-row matrices include deferred work and obsolete absence claims; they are not current acceptance denominators. Tests and files are not interchangeable with requirements.

**NM = NOT MEASURABLE — NO VERIFIED REQUIREMENT BASELINE.** This applies separately to source implementation coverage, functional acceptance coverage and integration acceptance coverage for every whole module below. No guessed percentage is supplied. The common status rule is: incomplete required behavior → PARTIALLY IMPLEMENTED; apparently implemented foundation without exhaustive acceptance → IMPLEMENTED BUT UNVERIFIED; intentionally excluded owner → DEFERRED TO V2. Verified slices are stated explicitly.
