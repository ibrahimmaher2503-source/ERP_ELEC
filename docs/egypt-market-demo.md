## حالات أعمال متنوعة بإذن المالك — 2026-11-02

```powershell
$env:ERP_DEMO_WORKFLOWS='1'
try { php -d opcache.enable_cli=0 artisan db:seed --class=ProjectsPurchasingWorkflowDemoSeeder } finally { Remove-Item Env:ERP_DEMO_WORKFLOWS }
```

## توسعة المشروعات والمشتريات — 2026-11-02

أضيف محليًا 120 مشروعًا جديدًا (12 لكل نوع: توريد فقط، تركيب فقط، توريد وتركيب، صيانة كهربائية، إحلال وتجديد، إنارة داخلية وخارجية، لوحات توزيع وتحكم، شبكات كابلات، أنظمة تيار خفيف، طاقة شمسية)، و360 مرحلة و1080 مهمة و360 معلمًا و720 احتياج مواد و240 مستندًا بمرفقات توضيحية خاصة. أضيفت أيضًا 300 مسودة طلب شراء و1800 بند، و250 مسودة أمر شراء و1500 بند، بكميات وأسعار عشرية ومجاميع متطابقة مع البنود. متغيرات الحجم: `ERP_DEMO_PROJECTS=120`، `ERP_DEMO_REQUISITIONS=300`، `ERP_DEMO_PURCHASE_ORDERS=250`، بحد أقصى 5000 لكل نوع. الهويات `DEMO-EG-VOL-*` ثابتة؛ إعادة التشغيل تتخطى السجلات الموجودة وتحفظ تعديلاتها.

أصبحت الإجماليات المحلية 124 مشروعًا و303 طلبات شراء و251 أمر شراء، كلها ضمن نطاق عرض حساب الإدارة 2. القوائم وتفاصيل العينات والمهام والمستندات أعادت HTTP 200 عبر Laravel HTTP kernel باستخدام الحساب الموجود ودون تجاوز middleware. إعادة تشغيل التركيبة الكاملة أضافت صفر سجلات أعمال. أُخذت نسخة PostgreSQL احتياطية خاصة قبل التحميل؛ الإيصالات والأعداد في `.tmp/volume-demo-20261101T235428Z/`. لم تنفذ اختبارات آلية أو تحقق بصري شامل. البيانات مسودات تخطيط فقط؛ لا اعتمادات أو تنفيذ أو استلام أو ترحيل أو أسعار سوق معتمدة، ولا حسابات أو صلاحيات جديدة. عروض الموردين وRFQ والاستلام تظل مرتبطة بمصادرها وإجراءاتها الحقيقية ولا تصطنع لتعبئة القوائم.

## التشغيل وإعادة التشغيل

```powershell
php -d opcache.enable_cli=0 artisan db:seed --class=EgyptMarketDemoSeeder
# أو الأمر الافتراضي الصريح في local/testing:
php -d opcache.enable_cli=0 artisan db:seed
```

القيم الافتراضية موضحة أعلاه. يمكن تغيير الحجم بمتغيرات البيئة `ERP_DEMO_PRODUCTS`, `ERP_DEMO_CUSTOMERS`, `ERP_DEMO_SUPPLIERS`, `ERP_DEMO_QUOTATIONS`, `ERP_DEMO_ORDERS`, `ERP_DEMO_BRANCHES`, `ERP_DEMO_USERS`. يتطلب `ERP_DEMO_ACTOR_ID` حسابًا موجودًا ونشطًا ومؤكد البريد يحمل صلاحية إدارة الأمان؛ الافتراضي المحلي2. لا ينشئ الـseeder مسؤولًا جديدًا أو يمنح أدوارًا أو نطاقات وصول.

يحصر الـseeder الكتابة في PostgreSQL المحلي `erp_elec_new` أو الاختبار `erp_elec_new_test` حسب البيئة. العملية متسقة داخل transaction مع قفل خاص بالبيانات التجريبية؛ فشل الحفظ ينظف الملفات الجديدة فقط. الهوية ثابتة، وإعادة التشغيل تتخطى السجلات الموجودة وتحفظ تعديلاتها وعلاقاتها. تم تشغيل التحميل الكامل ثم إعادته: التنفيذ الثاني أضاف صفر سجلات. لم يحدث reset أو حذف أو إعادة كتابة للشركة أو البيانات الموجودة.

## ما لا يتم ملؤه بشكل مصطنع

- بيانات الشركة القانونية الحالية لا تُستبدل بأرقام أو معلومات خيالية. المصنع الخاص بالشركة ينشئ singleton رقم1 في قاعدة اختبار فارغة فقط؛ المصنع الخاص بالفرع مرتبط به.
- الأذونات والأدوار وإسناداتها والنطاقات الأمنية لا تُنشأ لمجرد ملء الجداول. قاعدة Administrator الدائمة منفصلة عن الداتا التجريبية، وتظل حاكمة للصلاحيات الحالية والجديدة.
- حسابات الموظفين التجريبية معطلة وغير مؤكدة البريد، بكلمات مرور عشوائية غير قابلة للاستخدام العملي. لا يتم ادعاء دخول سابق أو إنشاء session/passkey/token/2FA مصطنع.
- سياسات التسعير والضرائب والتفويض والموافقة الذاتية والقوالب التجارية المعتمدة تحتاج إعدادًا معتمدًا؛ لا يتم وضع حدود أو نصوص معتمدة افتراضية من داخل الـseeder.
- العروض وأوامر البيع مسودات فقط، بلا أرقام إصدار رسمية أو طلبات/قرارات مراجعة أو قبول عميل أو تحويل أو حجز مخزون أو ترحيل مالي. أوامر البيع مباشرة وليست تحويلات مزعومة من العروض.
- جداول queue/cache/sessions/import receipts/audit تملؤها عملياتها الفعلية. لا تتم صناعة نجاحات استيراد أو أحداث تدقيق أو تشغيل غير حقيقية. تسجل فقط أحداث `demo.created` التي نتجت عن الإدخالات الفعلية.

بقاء بعض الحقول NULL له معنى صحيح: `removed_at` لملف لم يحذف، `parent_id` لتصنيف رئيسي، رقم إصدار لعرض لم يصدر، مصدر سعر معتمد غير متاح، أو بيانات قرار لم يسجل بعد. لا تستبدل هذه الحالات بقيم مضللة. تظهر الواجهة حالات عدم التوفر والجاهزية حيث تطلب العقود ذلك. نطاقات فروع أوامر البيع تظل صلاحية مستقلة؛ تحميل المسودات لا يمنح وصولًا إلى فرع.

## تغطية المصانع والتحقق

المصانع الحالية تغطي الشركة/الفروع/المستخدمين، تصنيفات/علامات/وحدات/منتجات/تحويلات/وسائط، جميع علاقات العملاء والموردين، العروض وبنودها ومرفقاتها، وأوامر البيع وبنودها. مصانع سياسات/طلبات الموافقات وإيصالات الاستيراد لا تستخدم في بيانات الموقع؛ هي fixtures لاختبارات معزولة فقط. أضيف `DataOperationItemFactory` وربطه بالنموذج، وأصلح تحويل الوحدة الافتراضي ليطابق بُعد وحدة الصنف الفعلي.

الفحص المركز `.tools/check-egypt-market-demo.php` مكتوب بواسطة Luna ومراجع من القائد. نجح على PostgreSQL الاختبار المنفصل: 21 تحققًا تشمل العلاقات والأعداد والحقول والملفات والحسابات وعدم تغيير البيانات السابقة وأمان الحسابات وإعادة التشغيل، مع rollback وتنظيف قرص ملفات خاص بالاختبار. نجحت كذلك فحوص المصانع السابقة، وفحوص Administrator، وPint على الملفات المعدلة. فحص النسخة المحلية النهائي موثق أدناه عند اكتماله. لم تنفذ full suites أو Playwright أو تدقيقًا بصريًا شاملًا.

## جرد قاعدة البيانات

الجرد التفصيلي في `.local/schema-inventory.json` يتضمن كل جدول وأعمدته وأنواعها وNULLability والقيم الافتراضية والعلاقات والقيود والفهارس والأعداد؛ لا يتضمن محتوى السجلات أو كلمات المرور أو بيانات الاعتماد. السكربت `.tools/describe-erp-schema.php` يعمل داخل transaction للقراءة فقط. تتم مطابقة ملفات الميجريشنز مع سجل التنفيذ، ولا تضاف جداول لمجرد جعل القوائم ممتلئة.

### نتيجة التحقق المحلية النهائية

التحميل المحلي الكامل نجح، والتشغيل الثاني أضاف صفر سجلات. فحص القراءة فقط `.tools/check-local-egypt-market-demo.php` تحقق من الأعداد السبعة، واكتمال حقول الأعمال ذات المعنى، واتساق العلاقات واللقطات والوحدات والتحويلات والكميات، ومن8800 ملف PNG/PDF خاص بمساراته وحجمه ونوعه وبصمة مرفقات العروض. بقيت حسابات الموظفين التجريبية معطلة بلا أدوار أو جلسات أو صلاحيات. سجلات الشركة والبيانات السابقة محفوظة. الجداول الأمنية والسياسات والاعتمادات لا تحتوي على بيانات مصطنعة لمجرد إخفاء حالة فارغة.
# M08 local/testing extension — 2026-10-30

`EgyptMarketDemoSeeder` now includes the explicitly invokable
`FieldMaintenanceDemoSeeder`. It adds one identifiable request draft
(`DEMO-EG-MR-001`), one standalone work-order draft (`DEMO-EG-WO-001`), one
configurable checklist (`DEMO-EG-CHK-001`) and one unstarted planned visit with an
inactive proposal assignment. Repeat runs preserve existing edits and add no
duplicates. No rates, actual labor, service approvals, stock/FIFO/GL movements,
invoices or completion events are seeded. See [M08 contracts](m08-field-maintenance.md)
and [Phase 3 acceptance](release/PHASE3_FIELD_MAINTENANCE_REPORT.md).
