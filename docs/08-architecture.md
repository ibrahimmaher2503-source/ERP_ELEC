# Architecture
Laravel 13 modular monolith; Livewire 4, Blade, Flux UI 2 free package, Tailwind 4 and Vite. Start from the official Laravel Livewire kit; installed stable dependencies are locked. No Flux Pro package or license bypass.
Keep the 17 owner names from 03-DOMAIN-MODEL-BOUNDED-CONTEXTS.md. Create app/Modules/<Owner>/{Domain,Application,Infrastructure,Presentation} only as real feature code needs those directories. Do not scaffold 17 empty implementations or generic CRUD engines.
Framework authentication remains in app/Models/User and app/Actions/Fortify; its business owner is Organization. Owner data is accessed through documented typed contracts. Implement only contracts actually required by the current producer/consumer; no shared mutable business service.
resources/views/layouts holds the app/auth shell. components/page/heading and components/ui/{panel,empty-state} are presentation-only; use Flux controls directly. resources/css/app.css owns theme/font tokens. Keep page-specific markup within its owner/page. Livewire bundles Alpine; never install it twice.
PostgreSQL is the only application/test database. File cache and database queue work without Redis; installed Predis enables switching CACHE_STORE and QUEUE_CONNECTION to redis when needed. Required stock/GL/subledger effects always commit synchronously together, never through a background queue. No external calls while holding business locks.
Persist UTC. ERP presentation timezone is Africa/Cairo. Locale ar defaults RTL; en uses LTR. Add only shared components that real repeated pages need.

Owner decision: factories are required for every new module's implemented business entities. Provide realistic, internally consistent synthetic data and an explicitly invoked local/testing demo seeder with repeat-run safety. Never overwrite existing company/account/master records or seed fake runtime/authentication/posting history. Shared security catalogs retain approved definitions; factory data does not imply default privileges. Technical infrastructure tables are populated by their actual runtime, not arbitrary fake rows.


Owner-approved Administrator defaults (2026-10-21): Organization PermissionAccess treats explicit Administrator membership as authority for every known PermissionCatalog key. Unknown permissions still deny. Normal account/scope/owner business guards remain in force. SyncAdministratorPermissions materializes all registered keys in role_permissions after migrations, increments the role version only on additions and appends an audit event; it preserves other roles, membership, direct grants and scopes. Administrator matrix is complete/read-only. All new modules inherit this rule automatically; no owner confirmation or manual enablement is required for each new permission. Automated role-only audits have null actor/subject rather than fabricated human attribution. This supersedes earlier security-only/no-automatic-grant Administrator statements; other role defaults remain unchanged.
