# مراجعة تجربة الصيانة — 2026-11-02

تقييم: الرحلة تحتاج معرفة مسبقة بترتيب العمل والتنقل بين الصفحات؛ الواجهة لا تقود المستخدم من البلاغ إلى الإغلاق بصورة واضحة. أعلى أولوية هي إرشاد الخطوة التالية وتصحيح أخطاء الإدخال.

## نطاق الدليل

- تصفح يدوي مصادق عليه للتطبيق المحلي على المنفذ 8000 بحساب Administrator: الصفحات العامة السبع، إنشاء الطلب، الطلب التجريبي، إنشاء أمر مستقل، والتبويبات العشرة لأمر العمل التجريبي.
- معاينة سطح المكتب 1600×900 والموبايل 390×844 لعينة من النماذج والتفاصيل والإغلاق. ليست مراجعة لكل المقاسات أو قارئات الشاشة.
- تغيير اختيارات نموذج جديد دون حفظ، ومحاولات إرسال نموذج مستقل ناقص عمدًا في حالتين: دون فرع، ثم بفرع فقط، مع إعادة الحالة الثانية لتوثيقها. ظهرت أخطاء ولم يُنشأ أمر عمل.
- لم تتغير سجلات الأعمال القائمة. لم تُسجل زيارة أو ساعات فعلية أو صرف أو اعتماد أو فاتورة أو إغلاق. السجل المتاح مسودة غير قابلة للفوترة؛ لذلك المراحل اللاحقة راجعت شروطها ونماذجها في المصدر، وليست دورة تنفيذ ناجحة مثبتة بالتصفح.
- لا اختبارات آلية أو تعديل لكود التطبيق أو منح صلاحيات أو نشر. لا بيانات دخول محفوظة في هذا التقرير.

## ترتيب الرحلة المقترح

1. **تسجيل البلاغ:** العميل والفرع والموقع ووصف العطل والأولوية والمسؤول، مع فصل التفاصيل الاختيارية. وضوح الفرق بين حفظ المسودة وتقديم الطلب.
2. **مراجعة الطلب:** تقديم ثم قبول/رفض حسب الصلاحية، وبعد القبول إنشاء أمر العمل. عرض المرحلة والمسؤول التالي دون إسقاط الاعتماد.
3. **تجهيز التنفيذ:** تعليمات التنفيذ ثم التكليف وجدولة الزيارة وقالب الفحص. جمع العرض لا يعني حذف كيانات التكليف والزيارة أو فحص التعارض.
4. **تنفيذ الزيارة:** البداية والتقرير والفحوص والصور والوقت والقطع في سياق الزيارة، مع حفظ الأدلة وتوضيح ما ثبت وما بقي.
5. **مراجعة الإتمام:** جميع الزيارات الإلزامية، الفحص المحسوم، الوقت لكل زيارة، الإقرار عند اشتراطه، وتسوية القطع؛ كل نقص له رابط.
6. **التحقق والفوترة والإغلاق:** الإتمام ثم التحقق الفني؛ للخدمة المدفوعة اعتماد تجاري مستقل وإحالة الفاتورة المطلوبة قبل الإغلاق. عرض المصدر الفعلي وحالته، دون مساواة الإغلاق بالتحصيل أو الترحيل المالي.

هذه مراحل عرض مقترحة، وليست حالات جديدة أو تفويضًا بتجاوز قواعد العمل.

## خطة التنفيذ المقترحة

- **المرحلة 1 — إزالة العوائق:** معالجة رسائل الإدخال وربطها، ترويسة الأمر والإجراء التالي، قائمة الجاهزية وروابط النواقص، وتصحيح مسميات المسار المستقل. معالجة التحقق والإسقاطات تحتاج تعديلًا وظيفيًا يراجَع منفصلًا عن تنسيق Blade.
- **المرحلة 2 — ترتيب الشاشات:** تجميع النموذج، تحسين سياق الزيارة، أسماء الفنيين والمراجع، تقارير صادقة عن المتاح، وفصل عرض التكلفة الإداري. إعادة استخدام `x-page.heading` و`x-ui.panel` وFlux والتنقل الحالي؛ لا مكونات عامة أو تبعيات جديدة دون حاجة متكررة.
- **المرحلة 3 — الصقل:** دلالات الحالات، حالات الفراغ والتحميل، وضوح الحفظ والتنقل بين النماذج، وتركيز لوحة المفاتيح. الألوان والحدود والمسافات من `resources/css/app.css` و`docs/design/UI_SYSTEM.md`؛ لا يلزم نظام تصميم جديد.

## حدود الاستنتاج

بيانات الديمو الحالية تُظهر أمرًا مسودة وتكليفًا سابقًا غير نشط وزيارة مخططة؛ ليست دليل تشغيل مكتمل. اختيار الفني المتاح أظهر مدير النظام فقط، وهذا وصف للإعداد الحالي لا حكم بخلل الصلاحيات ولا مبرر لإضافة منح. لم تختبر هذه المراجعة حساب فني منفصل، اعتمادًا تجاريًا، تسوية مخزون، تنزيل تقرير صادر، فقد اتصال، تحميل ملفات، قارئ شاشة أو أداء تحت حمل. لا تثبت جاهزية إصدار أو صحة مالية شاملة.
