# ERP business scenario catalog

This is the traceable scenario catalog for the capabilities found in M01–M04. IDs are stable; executable IDs are linked to checks in `.tools/run-safe-qa-checks.php`, while rows without an executable reference remain catalog-only. Each row follows the project scenario template: ID, module/feature/rule/title/priority, preconditions and permission, synthetic data/steps, expected result, actual result, test type and automated reference, evidence, defect, status, and notes.

The runner reports check-script results and maps each script to scenario IDs; that does not prove every mapped scenario passed independently. `NOT RUN` means no separate scenario-level result is available. Where a module receipt reports an earlier focused pass, the row states that separately. `BLOCKED` is reserved for real absent producers or current owner-contract dependencies; a passing readiness denial does not turn the missing operation into a pass. E2E IDs are not assigned until real browser workflows are executed. See the current run table in `TEST_COVERAGE_MATRIX.md` and its timestamped JSON receipt.
