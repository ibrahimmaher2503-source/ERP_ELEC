# M01 Stage06 — Integrated audit and security

User Details has four RTL tabs: المعلومات الأساسية, الأدوار ونطاقات الوصول, سجل الصلاحيات, الأمان والنشاط. Existing user actions, permission matrices and scope Actions are reused. No standalone audit/access page. Access history and security activity require verified M01.security_admin plus current target M01.user_view; the nested component and query reauthorize each read/mutation. Existing delegated status/password operations retain their separate permissions.

Organization access_audits remains authoritative for role/scope/direct-grant changes. System audit_entries remains authoritative for user/account/authentication events through the existing synchronous MasterChanged bridge. No duplicate recording of existing managed creation/update/status/reset Actions. UserSecurityHistory authorizes the target, then consumes the typed UserActivityReader contract implemented by System.ReadUserActivity. The returned snapshots allow only explicitly safe identity/status/session-revoked fields; no passwords, tokens, session payloads, IP/device tracking or raw login request bodies.

Migration 060 adds nullable outcomes and query indexes, and permits a null System audit actor. Existing append-only triggers remain intact. Old outcomes remain unknown; they are not backfilled as successful. New changes record succeeded/failed. Successful login records the authenticated actor and last-login time transactionally. Failed login attempts for recognized accounts record anonymous/unverified actor and failed outcome; unknown identities are not fabricated as user records. PasswordResetLinkSent captures actual link-dispatch metadata, not a guessed initiation. Existing reset completion remains audited once. Personal password changes recheck current credentials under lock, validate strength, clear old reset tokens, revoke sessions and audit safe completion metadata in one transaction. Personal profile updates also produce safe transactional events.

Permission history distinguishes direct user events from shared role-matrix events for currently assigned roles. The UI explicitly states that historical membership at the event time cannot be proven; shared-role changes are not falsely attributed to the target user. A reusable presentation-only audit timeline displays actor, event, scope, before/after, Cairo time and recorded outcome. Latest 30 access events / 50 security events are displayed, honestly labeled as bounded history rather than an exhaustive export.

No warehouse records/grants are introduced. Warehouse history remains unavailable until the M06 owning contract exists. Full suites, screenshots and QA acceptance remain deferred under Fast Development Mode.
